# 开发说明

## 目录结构

- `Sources/CalendarMonitor.swift`：监听苹果日历右键操作，保留原菜单并展示完成按钮。
- `Sources/CalendarAccessibility.swift`：读取日程标题、日历名称、日期时间和菜单位置。
- `Sources/CalendarService.swift`：EventKit 授权、查询、重新校验和保存本次日程。
- `Sources/CompletionCore.swift`：完成前缀、日期解析和日程精确匹配。
- `Sources/CompanionPanel.swift`：菜单旁的完成按钮浮层。
- `Sources/SettingsView.swift`：中文设置、授权状态和演示日程。
- `Sources/main.swift`：菜单栏应用入口和权限状态刷新。
- `Tests/CoreTests.swift`：24 项核心逻辑检查。
- `build.sh` / `setup-signing.sh`：构建应用并复用固定的本地签名身份。
- `package.sh`：生成中文 DMG、ZIP 和 SHA-256 校验文件。

## 本地签名

临时签名的应用每次重新编译后身份可能改变，导致 macOS 隐私授权失效。本项目在 `.build/Signing` 中创建固定的本地代码签名证书、私钥、专用钥匙串和随机口令，后续编译复用它们。

该证书只在当前用户范围被信任用于代码签名，不添加 TLS 或网站证书信任。构建期间暂时将专用钥匙串加入搜索列表，退出时恢复原列表。首次建立信任时可能出现 macOS 确认窗口。

**请保留并保护 `.build/Signing`，不要上传或共享。** 目录权限为仅当前用户访问；删除后会生成新身份，需要重新授权。`.gitignore` 排除该目录以及常见私钥、证书和钥匙串文件。发布的 app 只包含公开签名证书，不包含私钥或口令。下载安装包的用户不需要运行签名脚本或导入证书。

从最初的临时签名版本升级时，需要重新允许一次日历访问，并在辅助功能列表中移除旧条目、添加当前 app。之后同一身份的正常更新可继续使用既有授权。

## 构建与打包

```sh
./build.sh
./test.sh
./package.sh
```

目标为 `arm64-apple-macosx14.0`。构建在临时目录完成签名和严格验证，然后复制到项目目录，避免桌面文件元数据干扰签名。打包只收录应用与中文使用说明，不包含源代码、构建缓存或签名材料。

`dist/` 中生成以下文件：

- `CalendarClick-v0.1.0-macOS-arm64-zh-CN.dmg`
- `CalendarClick-v0.1.0-macOS-arm64-zh-CN.zip`
- `SHA256SUMS.txt`

DMG 内有应用、“应用程序”快捷方式和中文说明。ZIP 内有应用和中文说明。

## 发布检查

1. 保持应用标识 `local.davidsi.CalendarCheck`，复用原有签名身份。
2. 运行核心检查，验证安装包解压后应用的签名和架构。
3. 检查提交文件与安装包内容，确认不含签名私钥、钥匙串口令、个人日程或本机路径。
4. 将安装包、校验文件和中文版本说明放入 GitHub Release。

当前通过 Git 推送发布：将 `dist/` 的三个文件复制到 `releases/版本标签/` 并提交，再推送同名的 `vX.Y.Z` 标签。`.github/workflows/release.yml` 会核对校验和，使用 GitHub 自带的临时令牌创建中文版 Release 并上传附件，无需上传本机签名材料或配置个人令牌。

本地证书签名不等于 Apple Developer ID 签名或 Apple 公证。首次下载的打开说明应如实说明这一点。
